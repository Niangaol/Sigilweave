# 一幕地板重制 + 玩家朝向修正（验收记录）

> 起因（用户反馈，2026-10-24）：
> 1. 「人物往左走的时候面向右边，往右走的时候面向左边」
> 2. 「地板也要重新制作」
>
> 范围经用户确认：地板只做**第一幕**，二/三幕保持原样。

## 一、朝向 bug：根因与修法

**根因**：`player_sheet.png` 的 12 帧原画是**朝左**画的（脸、兜帽开口、前行的那条腿都在画面左侧；
见 `gongzhen/gongzhen/runtime/assets/sprites/player_spritesheet_pixelated.png` 的第 6 帧）。
而 `Player.drawSprite()` 里写的是 `setFlipX(this.facing < 0)`——它假设原画朝右，于是：

| 输入 | facing | 旧 flipX | 实际朝向 |
| --- | --- | --- | --- |
| 往左走 | -1 | true（镜像） | 朝右 ❌ |
| 往右走 | 1 | false | 朝左 ❌ |

**修法**：把判定收成一个导出函数 `flipXForPlayer(facing) => facing > 0`，并在注释里写明
「原图朝左，只有朝右才翻转」，避免以后又被人按直觉改回去。

- 法杖位置（`staffTipOf`）本来就跟着 `facing` 走，改完自动对齐：朝左杖在左、朝右杖在右，
  正好落在角色前进那一侧。
- 回归：`tests/player-facing.test.js`（3 条）锁定「朝左不翻转 + 法杖在左」的对应关系。
- 敌人（`Enemy.js` 的 `setFlipX(this.face < 0)`）**没动**：怪物素材原图朝右，逻辑本来就对。

## 二、地板重制

旧版 `Background.drawTiles()`：32px 大方格 + 每格 33% 概率随机换深浅 + 全长 1px 砖缝。
远看是**马赛克迷彩**，既没有石材质感也没有厚度。

新版 `drawFlagstones()`（只给 act=1 用，`drawTiles` 保留给二/三幕）：

| 层 | 做法 |
| --- | --- |
| 底 | 整铺近黑砖缝色 `#0b0813` |
| 铺装 | 横排错缝：每排起点随机左移、**每排行高随机**（ROW_H 减 0~5）、砖宽 22~46 随机、12% 概率出长条石 |
| 石色 | 五档明度（`#1a1527 → #38304f`）+ 两档只换色调的苔绿/暖褐，比例压在中低调 |
| 立体感 | 左上 1px 亮边（`#5c5283`）、右下 1px 暗边；65% 的砖打满高光、35% 只给 0.4 强度 → 地面有高低 |
| 破损 | 缺角（啃掉砖缝色）、底边/右边随机啃 1~2px、15% 砖上一条 1px 折线裂缝、3 条横穿多砖的长裂缝 |
| 苔与尘 | 16% 的砖下沿长一小撮苔（压 2~3px）；砖面角度随机撒单像素颗粒（点不会有直角，远看是麻面） |
| 明暗 | 7 处像素抖动堆出来的暗斑 + 原有的噪点层，打散规则排布 |

**性能**：石砖细节是一次性绘制（约 4 万条绘制指令）。如果直接塞进 `staticG`，
Phaser 每帧都要重放这 4 万条指令。所以改成**烘焙成一张世界尺寸纹理**再当 Image 贴回
（`bakeFloor()`，key 按世界尺寸缓存，同局重开直接复用；生成失败自动落回 Graphics 直绘）。

| 指标 | 实测 |
| --- | --- |
| 烘焙耗时 | 50~96 ms（只发生在进入一幕战斗时一次） |
| 静态层每帧绘制调用 | 由「数万条 Graphics 指令」降为「1 张 Image」 |
| 压测 p50 / p95 / p99 / max | 4.2 / 4.3 / 4.6 / 12.5 ms（150 敌 + 294 弹丸 + 200 碎片，20s） |
| 生命周期 | 连续重开 5 次，实体与显示对象回到基线，无累积 |

## 四、本轮没做

- 二幕「腐沼教堂」、三幕「星陨王庭」的地板仍是旧方格（用户本轮只要求第一幕）。
  新铺装已经写成按主题取配色的函数，只要给对应 `THEMES[act].floor` 补一套色就能铺开。
- 玩家立绘在 32px 下的辨识度问题仍存在（文稿规格如此），未擅自改尺寸。
