# 战斗画面外框：会随血量变旧的雕花画框（2026-11-16）

> 需求原文（2026-11-16）：「外围加一圈边框 像画框一样,要是动态的 样式随着角色的血量而变化」。
> 澄清结论（三问已答）：形态取 **B 雕花画框**；血量表现取 **全套（裂纹 + 脉动 + 碎屑 + 渗血）**；**本期只做横屏**。

## 0. 结论先行

- 新增 `src/ui/battle-frame.js`：一条 **8px 厚的黄铜/石面雕花画框**，压在 480×270 逻辑画布最外层，四角 14×14 角花带内嵌宝石，上沿居中有浮雕横梁。
- 框体分辨率无关，全部用 `pxRect` / `pxLine` / `pxPoly` 硬边像素绘制，不引入任何图片资源或依赖。
- 血量只读 `player.hp / player.maxHp`，驱动三层表现：**底色按档位替换 + 每帧脉动 + 裂纹/碎屑/渗血**。时钟用 `engine.now`，暂停与顿帧时整框自动冻结，跟现有特效层一致。
- 为了让 8px 框不压字，**顶栏下移 9px（33→42：8px 框体 + 1px 内描边余量）**、**罗盘左移 8px（panel.x 326→318，BOARD.left 346→338）**、**「最闲六格」细目右移 3px**。这三处是本期唯一改动既有布局的地方。

## 1. 目标与非目标

目标：

1. 画布四周有一圈读得出「装裱」的硬边画框：外描边、黄铜亮边、石质框身、内描边、四角角花、上沿纹样。
2. 血量变化时框体**连续可读**地陈旧化：颜色插值 + 三档结构损伤 + 低血心跳脉动 + 碎屑掉落 + 四角渗血。
3. 每帧绘制量可控（动态层 ≤ 60 个图元），不新增纹理、不新增贴图、不改渲染倍率。
4. 不动战斗逻辑、不动 `src/logic/*`、不改 `package.json` 与构建配置。

非目标：

- 不做竖屏（480×760）版本，本期 `isPortrait()` 直接不创建画框。
- 不给标题、幕间、结算、过场套框，只在 `BattleScene` 生效。
- 不做画框的「受击震裂」一次性演出（受击已有 `EffectsLayer` 红边，见 §6）。
- 不重画 HUD / 罗盘视觉，只平移坐标。

## 2. 几何契约

画布 480×270。框体厚 `band = 8`，内开口 `FRAME_INNER = { left: 8, top: 8, right: 472, bottom: 262 }`（即 x 8..471、y 8..261，可绘制区 464×254）。

从外到内的 8px 分层（`pxRect` 逐条填充）：

| 偏移 | 厚度 | 色（完好态） | 作用 |
| --- | --- | --- | --- |
| 0 | 1 | `C.outline` | 外硬描边，把画框从屏幕边缘切出来 |
| 1–2 | 2 | `C.brassDark` | 黄铜暗部 |
| 3 | 1 | `C.brass` | 黄铜亮棱（血量越高越亮） |
| 4–6 | 3 | `C.stone` | 石质框身（血量越低越腐化） |
| 7 | 1 | `C.outline` | 内硬描边，与画面分隔 |

四角角花：`14×14`，覆盖框体并向画面内凸出 6px；形制为黄铜描边 + 内嵌 `4×4` 菱形宝石（`C.teal` → 低血 `C.blood`）。

上沿横梁：以 `x=240` 居中，宽 120、高 8，三连菱形 + 中线纹样；左右两侧各一段 40px 短竖纹（每 8px 一个凹槽）。左右与下沿每 32px 一个 `4×2` 竖向凹槽。

## 3. 血量驱动契约

纯函数 `frameTone(ratio)`（`ratio = clamp(hp / maxHp, 0, 1)`）返回：

```
{ tier, breathHz, pulseHz, crackCount, debrisPerSec, seep, bloodMix, gemColor }
```

| tier | ratio 区间 | breathHz | pulseHz | crackCount | debrisPerSec | seep | bloodMix |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `intact` | > 0.6 | 0.30 | 0 | 0 | 0 | 0 | 0 |
| `worn` | 0.3 < r ≤ 0.6 | 0.20 | 0 | 3 | 0 | 0.35 | 0.35 |
| `failing` | ≤ 0.3 | 0 | 1.10 | 6 | 4 | 1.0 | 1.0 |

- `bloodMix`：框身/黄铜向 `C.blood` 线性插值的比例，用局部 `mixColor(a, b, t)` 实现（`Palette.js` 没有现成混色函数，不往公共色板里加）。
- 档位切换时才重绘「底色 + 裂纹」两层；`alpha` 级联的呼吸与脉动走每帧动态层。
- `pulseHz = 1.10` 与 HUD 低血闪烁（`Hud.js:67` 的 `Math.floor(now/220) % 2`，约 1.14Hz 同向）刻意对齐，读作同一颗心脏。

裂纹（`frameCracks(seed, count)`）：

- 用确定性种子（`run.seed + ':frame:' + stage`，避免每档重绘时裂纹位置跳变）生成 `count` 条折线，每条从某条边上的随机起点出发，沿法线向内 **4~6px**（加 1px 内衬高光最多到 7px），带 1px 左右抖动。**深度必须小于 `band=8`**：内开口从 x/y=8 起就是 HUD 与罗盘的地盘，裂纹只能裂在框身上，越界会把罗盘面板切出一道口子（终审 I1 的实证就是这个）。
- 每条裂纹画两遍：1px `C.void` 底 + 1px `mixColor(C.brassDark, C.blood, bloodMix)` 高光。

碎屑：

- 仅在 `failing` 档、按 `debrisPerSec = 4/s` 生成，最多同屏 8 个；以 `2×2` 为主（`1×1` 占 1/3）。**只从左右两条竖框生成**，落点收在框身向内 3~6px 的窄带里，横向抖动也被夹在窄带内：碎屑整段寿命都沿框身下滑（下沿一生成就出画，不掉；上沿掉渣要横穿整幅画面才落地，读作画面里的噪点而不是画框在碎，终审 nit 3 之后删掉了这条路）。
- 重力按**可见性**标定，不照抄 `0.06 px/ms²`（那是 100ms 内飞出画面的加速度）：取 `+0.0002 px/ms²` + 初速 `0.02~0.05`，单颗落地约 1.5s，寿命 `2600ms`。稳态同屏 4~6 颗，空帧 <1%。

渗血：

- `seep > 0` 时四角内侧各画 `2×2` 到 `2×10` 的暗红（`mixColor(C.bloodDark, C.blood, seep)`）竖向渗痕，长度随 `sin(now / 900)` 呼吸。

## 4. 挂载与分层

- `BattleFrame` 在 `BattleScene.create` 里、`this.mountUiLayer()` **之前**构造：三个 `scene.add.graphics().setScrollFactor(0)`，深度 `6000 / 6001 / 6002`。
- `mountUiLayer`（`BattleScene.js:338`）会把所有 `scrollFactor === 0` 的对象按 `depth` 排序塞进 `uiRoot`（容器深度 5000），所以 6000+ 的画框天然排在最后 → 压在所有 HUD、罗盘、暂停菜单、问答面板之上。
- 不挂进容器的画框会被摄像机 `zoom` 推离屏幕，因此**必须**走这条既有路径，不允许 `setScrollFactor(0)` 后单独留在场景根上。

## 6. 与既有特效的关系

- 受击红边（`EffectsLayer.js:583-594`）画在 `vg`（depth 940），会被 depth 6000 的画框盖住外侧 8px —— **这是期望效果**，红边从框内缘开始读作「画面被震了一下」而不是「画框被震」。因此**不改**该处代码。
- 暗角脉冲 `vignette` 同理，只在框内可见，视觉上反而更像镜头在画框里收放。
- 低血时画框的 `pulseHz` 与 HUD 低血闪烁同频，两者一起读作同一套血量语言。

## 7. 纯逻辑与测试

`src/ui/battle-frame.js` 导出纯函数（不 import Phaser，只 import `Palette.js`，与 `Hud.js` 同款）：`FRAME`、`FRAME_INNER`、`frameTone(ratio)`、`frameCracks(seed, count)`、`mixColor(a, b, t)`。

`tests/battle-frame.test.js`（用 `tests/editor-ui.test.js` 的 fake graphics 套路）覆盖：

1. `frameTone` 三档边界：1.0 / 0.61 / 0.6 / 0.31 / 0.3 / 0 / 负数 / NaN 都有确定结果且不抛错。
2. `frameCracks` 同种子同结果、不同种子不同结果、每条裂纹端点都落在框体内且长度在 4~6px；200 个种子下所有裂纹点（含高光偏移）都不进入内开口。
3. `FRAME_INNER` 与 `band` 自洽：`left === band`、`right === 480 - band`、`bottom === 270 - band`。
4. 碎屑可见性：模拟 30 秒 `failing`，同屏峰值 ≥ 3、空帧占比 < 30%、且 ≤ 8（上限用字面量断言，另有一条 `FRAME_DEBRIS_CAP === 8` 的守卫）。
5. 动态层绘制量：碎屑撑满 8 颗的最坏帧，单帧 `fillRect` 调用数 ≤ 60；碎屑 30 秒内每一颗都落在左右 8px 框身里（`offBand === 0`）。
6. 暂停：`dt=0` 且 `now` 冻结时，碎屑状态与动态层这一帧的图元序列都逐字不变。

## 8. 交给实现者的部分

- 角花与上沿横梁的具体纹样像素排布（只约束尺寸 14×14 与 120×8）。
- 裂纹的折线抖动幅度与 1px 高光的落点。
- 碎屑的颜色（建议 `C.brassDark` / `C.mauve` 各半）。
