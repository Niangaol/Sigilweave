# 技术架构（接手地图）

这份文档回答三件事：代码怎么分层、数据怎么在层间流动、要加东西该动哪几个文件。第一天只需要读它，再去翻 [规则契约](<规则契约.md>) 和 [内容规格表](<内容规格表.md>) 对数值。

## 一、分层与目录

| 目录 | 文件 | 职责 | 边界 |
| --- | --- | --- | --- |

## 二、关键数据流

1. **幕间 → 快照**：`IntermissionScene` 用 `createWorkshop({ draft: draftFromGrid(preview, { act: chapter }), shards, seed: run.seed + ':' + chapter })` 编辑草稿 → `canDepart` 放行 → `applyDraft(grid, draft, { phase: 'intermission' })` 一次原子提交 → `run.draft = result.snapshot`。
2. **快照 → 战斗（只读）**：`BattleScene.create` 里 `createGrid()` 后 `applyDraft(this.grid, this.run.draft)`，`!committed.ok` 直接抛 `战斗构筑快照无效`；再用 `rebuildDerived(grid, ACTS[chapter-1].baseIntervalMs * buffs.intervalMul, { cooldownMul })` 派生间隔与冷却。战斗内没有任何改阵入口。
3. **伤害唯一入口**：`effects.applyDamage(enemy, amount, now)`，顺序固定 **盾 → 甲 → 血**。盾只置 `shieldBrokenPending`，眩晕/碎片/回收由 `Enemy.update → consumeShieldBreak` 消费；`armor` 只归 `bulwark` 行为所有（架盾 0.55，其余 0）；返回值只统计扣血，`lastBlocked` / `lastHitAmount` 是给表现层读的只读字段。尸爆、献祭、星陨、召唤物伤害全走这里。
4. **刷怪 RNG 顺序（契约）**：`updateSpawner` 先算槽位预算 `room = dif.maxAlive - enemySpawnLoad(enemies)` → `spawnWave` 用 `pickWavePoints` 一次抽一波落点 → 逐只 `spawnEnemy`：`pickEnemyType(chapter, combatRng.next())` →（天生精英跳过）`pickEnemyVariant(chapter, base, combatRng.next())` → `composeEnemyDef` → `new Enemy(...)`。波后间隔抖动还吃一次 `combatRng.next()`。这个顺序是 `scripts/density-sim.mjs` 复现历史基线的前提，改调用次序等于换基线。
5. **敌方弹道与召唤**：`enemy-ai.js` 只在出手帧产出 `melee` / `shots` / `summon`；`hostile.js` 推进单张列表，上限 `HOSTILE_LIMITS`：弹丸 96、召唤物 20、炮台 12、符文 8、追踪 16。场景侧只做跨列表统计与绘制。
6. **确定性 seed**：一切随机走 `Rng`（`hashSeed` 起手，`next()` 返回 [0,1)）。同一 `seed` 的脉流、刷怪、变体抽取、问答都同序，`?seed=` 与 `density-sim --seed=` 共用这套口径。

**铁律**

- 渲染不能反向决定玩法结果：伤害、冷却、触发只由 logic 层算。
- 卡牌数值只改 `src/data/cards.js`，场景里不写死。
- 一个场景一次提交：战斗内不得改阵。
- 表现层的动画读传进来的 `now`（通常是 `engine.now`），暂停与顿帧一起冻结。

## 四、扩展点（按代码顺序）

### 加一个法术

1. `src/data/cards.js` 的 `SIGIL_DEFS` 加条目：`name/damage/cdMul/kind`，需要就加 `slow/slowMs/radius/shield/heal/castMs`（`castMs` 是前摇毫秒，`effects.castTimeOf` 读它）。
2. 变体自动派生：`variants.js` 遍历 `SIGIL_DEFS` 生成锐/谐；终局法术加进 `COMBO_LOCKED` 就只有标准形态。
3. 新 `kind` 才动 `src/logic/effects.js` 的 `resolveSigilTrigger` 分支，并补单测；已有 `single/fan3/area/ward/chain/pierce/echo/nova` 直接复用。
4. `workshop.js` 的 `CARD_POOL` 加入池；`roster.js` 的 `SIGILS` 补 8×8 字模与 `color`。
5. `factions.js` 的 `SIGIL_FACTION` 登记派系；`evolutions.js` 补两条路线（缺了就是构筑校验报 `unknown_evolution`）。
6. 特效：`src/ui/spell-fx/spells/*.js` 里加条目并登记进 `FX_DEF_IDS`；漏登记只会回退成菱形弹丸，不白屏。
7. `card-hints.js` 补一句提示，跑 `npx vitest run --pool=threads tests/new-sigils.test.js tests/spell-fx.test.js`。

### 加一种敌人

1. `src/data/roster.js` 的 `ENEMY_TYPES` 加定义（`id/name/radius/damage/shards/behavior/hpMul/speedMul/color`，天生精英加 `elite: true`）。
2. `src/logic/enemy-ai.js` 的 `AI_PROFILE` 加 `defId: { behavior, tune, melee?, ranged? }`。它同时是 `KNOWN_DEFS` 的来源：未登记的 defId 一律回退 `skeleton`，所以漏加不会崩，只会变成走路怪。
3. 只有需要全新行为时才写 `stepXxx(brain, ctx)`：随机只走 `nextRandom(brain)`，位移/瞄准/开火复用 `approach / holdBand / beginCast / makeVolley / pushShot`，最后一发发多少由 `RANGED_RULES` 那条记录的 `count` 决定（`ring: true` 时均分整圈，`eclipse_priest` 就是一次 8 发），最后注册进 `STEP_BY_BEHAVIOR`。同一模式换数值只在 `AI_PROFILE` 加一行。
4. 攻击别写进 `stepXxx`：近战在 `MELEE_RULES`（`range/arc/windupMs/cooldownMs/kind`），远程在 `RANGED_RULES`（`count/spread/speed/lifeMs/kind`，追踪/炮台/符文按现有字段扩展），再在 `AI_PROFILE` 挂 `melee` / `ranged`。
5. `CHAPTER_ENEMY_WEIGHTS` 把 defId 加进对应幕，**每幕权重和必须是 1**。
6. 测试：`tests/enemy-ai.test.js` 补节拍与确定性，`tests/hostile.test.js` 补弹道/召唤边界，刷怪权重用例补一条。

### 加一种变体

1. `src/data/enemy-variants.js` 加 `ENEMY_VARIANTS` 条目（`hpMul/speedMul/damageMul/scale/radiusMul/shardsAdd/cost/minChapter/parts[]/shieldHpMul/tint`）。一次性护盾写 `shieldHpMul > 0`（重甲是 0.60），`parts` 可挂多件（重甲 `['pauldron','shield']`）。
2. 每幕 `CHAPTER_VARIANT_WEIGHTS` 加键并把和调回 1（差额给 `normal`），同时把 id 加进模块内的 `VARIANT_ORDER`——累积命中按这个数组的声明顺序结算，顺序错了等于换抽卡分布。
3. 配件纹理由 `src/ui/variant-parts.js` 的 `VARIANT_PART_TEXTURES` 生成 `var_<part>`（硬边像素、无渐变、无 `Math.random`）；有同名美术 PNG 时 `BootScene` 预载会优先用它，缺纹理自动降级成「无配件」。
4. `cost` 进 `spawn.enemySpawnLoad` 的槽位预算：cost 2 的怪顶两只，一波可能只塞得下一只。
5. 测试：`tests/enemy-variants.test.js`（表、权重和=1、`minChapter` 门槛、累积命中、`composeEnemyDef` 不改入参），带盾补 `shield-effects`，配件/缩放补 `enemy-variant-entity`。

### 加一条进化

1. `src/data/evolutions.js` 在该法术的数组里追加 `{ id, name, desc, mods }`，一条法术最多两条。
2. `mods` 只写「相对基础法术的增量/替换」，没写到的字段保持基础值。已接线的字段：`damageMul`（`effects.damageMultiplier`）、`cdMul`（`grid.rebuildDerived` 派生冷却）、`slow/slowMs/radius/heal/shield/shieldCap/freezeMs/vulnMs/vulnFactor/burnFactor/rootMs/armorBonus/jumps/decay`（`effects` 各分支读）。
3. 新字段必须先在 `effects.js` 加读取分支，否则数据写了等于没写。
4. 构筑校验不用改：`build.js` 用 `evolutionOf(defId, evo)` 判存在性，认不出就报 `unknown_evolution`。
5. 测试：`tests/evolutions.test.js` 补路线存在性与 mods 生效。

### 加一道 Boss 题（遭遇问答）

1. `src/data/encounters.js` 的 `ENCOUNTERS` 加条目：`clues[] / question / choices[] / correctChoiceId / explanation / successText / failureText / reward / penalty`。
2. id 有约定，别自创：`npc-<场>`、`miniboss-<场><a|b|c|d>`、`boss-<场>`。`acts.js` 的 `minorBossIdsOfStage` / `encounterIdsOfStage` 按幕-场表生成，手写 id 对不上就永远抽不到。
3. 状态机不用改；奖励由场景在 `confirmChoice` 首次成功时消费一次。答对大 Boss 走 `boss.resolveBossOnce` 的统一收据，别在场景里另发奖励。
4. 题干只能依赖本次展示的线索，否则玩家没法推。
5. 测试：`tests/encounters.test.js` 补正确项可推、奖励只发一次。

### 加/改一段过场

- 时间轴与字幕只在 `src/data/cinematics.js`：`TIMELINES` 控时长、`ACT_CARDS`/`STAGE_CARDS` 控幕名与字幕；新类型要同步 `buildTimeline`/`buildCard`。
- 画面在 `src/ui/cinematic-art.js`（`drawVeil/drawStage/drawSeal/drawSparkBurst`，都是「清空由调用方负责」的纯绘制）。
- 接入只走 `playCutscene(scene, { to, kind, act, stage, payload, report })`；目标场景拿到 `__cine: true` 时跳过自己的淡入。`?cine=0` 与 `?stress=1` 会自动退回普通切场。

### 调密度与平衡

- 密度只在 `roster.js` 的 `DIFFICULTY` / `ACT_DENSITY`，由 `difficultyAt(now, stage)` 统一给出，场景里不另写一套。
- 先用 `node scripts/density-sim.mjs`、`node scripts/simulate.mjs`、`node scripts/balance-lab.mjs` 验证，拍板后再改默认值。
- URL 对照参数（`interval/starts/duo`）只用于对比实验，默认玩法不受影响。

## 五、测试与跑法

```bash
NODE_OPTIONS="--require ./scripts/sandbox-noexec.cjs" npx vitest run --pool=threads
```

86 个文件、1774 项，全绿（本机实测）。`sandbox-noexec.cjs` 是本地沙箱专用开关：vite 在 Windows 上会 `exec('net use')`，沙箱禁子进程管道会抛 EPERM 导致整场起不来；这个 shim 把 `child_process.exec/execSync` 换成空实现，让 vite 走 `fs.realpathSync` 的普通分支。只在受控本地环境用。

| 层 | 命令 | 覆盖 |
| --- | --- | --- |
| 单文件 | `npx vitest run --pool=threads tests/hostile.test.js` | 改哪测哪，最快 |
| 纯逻辑仿真 | `node scripts/simulate.mjs`、`node scripts/balance-lab.mjs` | 冷却/共鸣/对照实验 |
| 战斗仿真 | `node scripts/density-sim.mjs 1 180 bolt` | 密度与击杀节奏，`--no-variants` 关掉变体抽卡的对照组 |
| 模糊测试 | `node scripts/fuzz.mjs`（`FUZZ_ROUNDS=300`） | 随机构筑 + 随机暂停，找异常与 NaN |
| 浏览器 | 先 `npm run dev`（5173）或 `npm run build && node scripts/static-server.mjs dist 4174` | playwright + 系统 Edge |
| 截图验收 | `BASE_URL=http://127.0.0.1:4174 node scripts/mow-fx-shot.mjs` 等 | 割草密度、逐法术特效，产物进 `docs/mow-fx/` |
| 全流程 | `node scripts/five-act-smoke.mjs`、`node scripts/workshop-smoke.mjs` | 五幕七场、幕间构筑 |
| 压测 | `node scripts/stress.mjs`（`LONG=1` 跑 120 秒） | 150 敌 / 300 弹 / 200 碎片帧时间 |
| 文档 | `node scripts/check-docs.mjs` | 全仓 markdown 相对链接是否都指向真实文件 |

浏览器类脚本默认走 `chromium.launch({ channel: 'msedge' })`，需要本机装了 Edge；`BASE_URL` 覆盖地址；只有 `layout-smoke.mjs` 读 `BROWSER` 变量，`BROWSER=firefox` 可在它上面换 Firefox。

## 七、已知约束与坑

| 约束 | 说明 |
| --- | --- |
| 纯逻辑不得引 Phaser / DOM | `src/logic/`、`src/data/` 里出现 `import 'phaser'` 就是错层；单测直接 import 这些模块就是因为这条 |
| 不用 `Math.random` | 全部随机走 `Rng`（`combatRng.next()` / `nextRandom(brain)`）；偷用一次，回放与 density-sim 基线同时失效 |
| 禁 `setTimeout` 驱动玩法 | 定时用 `EventQueue(now)` 与场景 `update(dt)`；动画读 `now`，暂停/顿帧自动一起停 |
| 480×270 逻辑画布 + 整数倍缩放 | `main.js` 放得下 2 倍就取整数倍（上限 8），不够 2 倍走分数倍率 × DPR（封顶 2）；竖屏加高到 760，`CONSOLE_TOP` 以下是触控台，游戏坐标一处不改 |
| `CutsceneScene` 必须注册在场景列表最后 | 它是覆盖层，注册靠前会被别的场景盖住 |
| 战斗内不得改阵 | 快照在幕间一次提交，战斗只读 |
| 变体权重的两个硬条件 | 每幕权重和 = 1；`VARIANT_ORDER` 的声明顺序即累积命中顺序 |
| behavior 名全局唯一 | 不要在 roster 或场景里另写一套节拍；`AI_PROFILE` 是唯一事实源 |
| 攻击层不冻结行为节拍 | 抬手只记时间，发射帧用 `leadAim` 现算；不要再存瞄准快照或画瞄准线 |
| `HOSTILE_LIMITS` 由场景跨列表统计 | `hostile.js` 只管单列表推进，别在里面加全局计数 |
| `spell-fx.js` 只是转发 | 改实现去 `src/ui/spell-fx/` |
| 不要给敌人加护甲/抗性字段 | `armor` 只归 `bulwark` 架盾；变体的护盾是一次性吸收 |
| dev 端口固定 5173 | `strictPort: true`，被占直接失败；`watch.ignored` 跳过 `*.tmpdir` / `*.tmp`，否则 Windows 下原子编辑报 EBUSY |

**已知技术债**

- 伤害数字等文本特效未池化；Boss 没有阶段转换。
- `EncounterPanel` 与场景耦合较紧，新增弹窗类交互要小心。
- 冷却在基础间隔下的存在感偏弱，属待拍板的设计问题（见 [平衡实验](<平衡实验.md>)）。
