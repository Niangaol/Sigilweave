# 技术架构与扩展指南

> 面向后续维护：模块职责、数据流、扩展点与测试策略。规则依据见 [规则契约](规则契约.md)。

## 一、分层

    src/logic/     纯逻辑，不依赖 Phaser，可被 Node/Vitest 直接导入
      constants.js   4×4 拓扑、间隔/冷却、幕配置等常量
      rng.js         确定性随机源（种子可复现）
      queue.js       (time, seq) 稳定事件堆
      grid.js        格子、邻接、出口、派生间隔/冷却
      engine.js      脉流主循环：触发、吞跳、改道、消散、联组事件
      combo.js       联组形状生成与严格时序判定
      sector.js      4×4 方位索敌（摄像机视口过滤，只打屏幕内）+ 每格方向齐射（VOLLEY_LIMITS）
      effects.js     伤害/护盾/减速/献祭/星陨等结算
      build.js       构筑校验、原子提交、快照
      workshop.js    幕间交易（选牌、换卡、铭文、出发校验）
      encounters.js  遭遇问答状态机
      boss.js        Boss 弹幕模板与击败收据
      enemy-ai.js    敌人行为（直线/正弦/保持距离/冲锋）
      pool.js        对象池
      run.js         单局会话（跨场景共享的最小数据）
    src/data/        cards.js（唯一数值源）、roster.js（视觉与敌种）、encounters.js（题库）、cinematics.js（过场时间轴与字幕）
    src/scenes/      Boot / Title / Battle / Intermission / GameOver / Cutscene（覆盖层，必须注册在最后）
    src/entities/    Player / Enemy / Boss / Projectile / Shard
    src/ui/          Background / SigilBoard / EffectsLayer / Hud / PauseMenu / EncounterPanel / Palette
                     spell-fx.js（16 个法术各自的飞行体/拖尾/起手/命中/护盾/连接线像素特效，纯绘制）
                     cinematic-art.js（过场三幕剪影/符环/浮尘/碎片，纯绘制）
                     transition.js（playCutscene 统一入口；?cine=0 兜底直切）
    src/audio/       Sfx.js（WebAudio 合成，无素材）

## 二、关键数据流

1. 幕间：`IntermissionScene` 用 `createWorkshop(preview)` 编辑草稿 → 出发前 `canDepart` → `applyDraft(grid, draft)` 一次提交，产出**冻结快照**存进 `run.draft`。
2. 战斗：`BattleScene.create` 从快照恢复法阵（战斗中不可编辑）→ `SigilEngine` 只读法阵推进脉流 → 事件回调驱动视觉/音效 → 伤害统一走 `effects.js`。
3. 幕末：计时到点开启 Boss 前置问答（`encounters.js`）→ 答对走 `boss.js` 结算收据并直接处决；答错进入真实 Boss 战。
4. 结算：`resolveBossOnce` 保证每幕只发一次奖励；三幕 Boss 全部解决后进入 GameOverScene 的胜利分支。

**铁律**：
- 渲染不能反向决定玩法结果；伤害/冷却/触发只由 logic 层计算。
- 卡牌数值只改 `src/data/cards.js`，不要在场景里写死。
- 一个场景一次提交：战斗内不得改阵。

## 三、扩展点

### 加一张符印
1. `src/data/cards.js` 的 `SIGIL_DEFS` 增加条目（name/damage/cdMul/kind/附加字段）。
2. 若需要新结算分支，在 `effects.js` 的 `resolveSigilTrigger` 增加 kind 分支，并补单测。
3. 加入 `workshop.js` 的 `CARD_POOL`；如需新图案，在 `roster.js` 的 `SIGILS` 加 8×8 像素字模。
4. 跑 `npm test` 与 `node scripts/three-act-smoke.mjs`。

### 加一种敌人
1. `roster.js` 的 `ENEMY_TYPES` 增加定义（hpMul/speedMul/damage/shards/behavior）。
2. 在 `enemy-ai.js` 增加 behavior 分支（纯逻辑，可单测）；`Enemy.js` 只负责转发与绘制。
3. 调整 `pickEnemyType(act, roll)` 的幕权重（权重和必须为 1）。
4. 在 `tests/enemy-ai.test.js` 补确定性与边界用例。

### 加一次遭遇问答
1. `src/data/encounters.js` 增加定义（clues/question/choices/correctChoiceId/reward/penalty）。
2. `getEncounterForAct` 或自定义触发点接入；状态机不要改，奖励仍由场景在 `confirmChoice` 首次成功时消费。
3. 注意：题干只能依赖当次展示的线索；答对 Boss 一律走 `resolveBossOnce` 统一收据。

### 加一个法术特效
1. 在 `src/ui/spell-fx.js` 的 `SPELLS` 增加 16 项之外的新条目：`silhouette / trail / colors / opBudget` + 六个绘制函数（projectile/trailFx/cast/impact/ward/link）。
2. 把 defId 加进 `FX_DEF_IDS`；`SPELL_FX` 自动生成。未知 defId 自动回退旧菱形弹丸，不会白屏。
3. 颜色与 `src/data/roster.js` 的 `SIGILS[defId].color` 保持一致（罗盘字模/方位光迹/触发闪光都吃这个色）。
4. 跑 `npx vitest run --pool=threads tests/spell-fx.test.js`。

### 加/改一段过场
- 时间轴与字幕只在 `src/data/cinematics.js`：`TIMELINES` 控时长，`ACT_CARDS` 控幕名与一句字幕；新增类型时 `buildTimeline`/`buildCard` 同步加分支，并补 `tests/cinematics.test.js`。
- 画面在 `src/ui/cinematic-art.js`：`drawVeil` / `drawStage` / `drawSeal` / `drawSparkBurst` 都是“清空由调用方负责”的纯绘制，只吃 Palette 的硬边工具。
- 接入只走 `playCutscene(scene, { to, kind, act, payload, report })`；目标场景拿到 `__cine: true` 时跳过自己的 `fadeIn`。CutsceneScene 必须保持在 `src/main.js` 场景列表最后。

### 调整割草密度
- 密度只在 `roster.js` 的 `DIFFICULTY` / `ACT_DENSITY`：生命、移速、生成间隔、同屏上限、每波只数、接触伤害。
- 刷怪波次在 `BattleScene.updateSpawner / spawnWave`：落点由 `spawn.js` 的 `pickWavePoints` 抽取（屏幕外 275~380），同屏拥挤由 `separateEnemiesBucketed` 空间分桶分离。
- 实际生成间隔与上限都由 `difficultyAt(now, act)` 给出，不要在场景里另写一套数值。

### 调整平衡
- 默认值只在 `constants.js / cards.js / roster.js`。可以用 URL 对照参数先验证（`interval/starts/duo`），拍板后再改默认。
- 改完必须重跑 `node scripts/simulate.mjs` 与 `node scripts/balance-lab.mjs` 更新数据。

## 四、测试策略

| 层 | 工具 | 覆盖 |
| --- | --- | --- |
| 纯逻辑 | Vitest（29 个文件、750 项） | 引擎确定性、构筑边界、交易、问答、Boss、敌人 AI、结算、池、难度密度、16 法术特效描述符 |
| 静态检查 | `scripts/fuzz.mjs` | 300 组随机配置 + 随机暂停 |
| 浏览器（无启动权限时） | 同源探针 + 任意浏览器（按仓库约定探针脚本不入库） | 真实 canvas 快照：密度、割草瞬间、16 法术飞行/命中、150 敌帧时间（结果写 `docs/mow-fx/`） |
| 浏览器 | Playwright + 系统 Edge / Firefox | 布局、工作台、问答双路径、三幕通关、说明面板、对照开关、割草密度与逐法术特效截图（`scripts/mow-fx-shot.mjs`） |
| 性能 | `scripts/stress.mjs`（可 `LONG=1` 跑 120 秒） | 150 敌 / 300 弹丸 / 200 碎片帧时间与池统计 |

## 五、部署

- 推送 `main` 触发 `.github/workflows/pages.yml`：`npm ci → npm test → npm run build → deploy-pages`。
- 测试不过不会发布；线上地址 <https://niangaol.github.io/Sigilweave/>。
- 本地静态验证：`npm run build && node scripts/static-server.mjs dist 4174`。

## 六、已知技术债

- 伤害数字等文本特效未池化；Boss 无阶段转换；`EncounterPanel` 与场景耦合较紧，新增弹窗类交互需谨慎。
- 冷却在 2.0s 基础间隔下的存在感偏弱（见 [平衡实验](平衡实验.md)），属待拍板的设计问题，不是实现缺陷。
