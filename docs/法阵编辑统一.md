# 法阵编辑统一：一个组件、两处复用（2026-11-10）

> 用户原话：「现在有两个不同的法阵编辑界面，把两个统一了，增加更明显的引导和更丰富的设计」。
>
> 改前：战斗内按 E 的「编辑法阵」（4×4 大格子 + 右侧窄手牌条）与幕间「构筑台」（上方奖励 + 左侧密排格子 + 右侧手牌/铭文/誓约）是两套独立绘制，面板、格子、手牌、按钮的视觉与交互都不一致，也没有统一的操作引导。

## 一、统一方式

新增共享视觉层 **`src/ui/editor-ui.js`**，两处编辑器调用同一组组件：

| 组件 | 作用 |
| --- | --- |
| `kitPanel` | 分区面板：不透明底 + 双层黄铜框 + 四角铆钉 |
| `kitHeader` | 顶栏：菱形纹章 + 标题 + 副标题 + 碎片徽章 |
| `kitSteps` | 三步引导条：选牌 → 放位 → 绑定/收回，当前步黄铜、已完成青色 |
| `kitCell` | 4×4 符位：状态条 + 区位装饰 + 图标 + 名称 + 铭文点 + 出口数 + 目标箭头 |
| `kitHandRow` | 手牌行：图标 + 名称×数量 + 效果说明，选中整行青框 |
| `kitDetail` | 详情面板：标题 + 图标 + 多行说明 |
| `kitAction` | 主按钮：青框亮底 primary / 暗底黄铜普通 |

两处共用同一份卡牌效果文案 **`src/data/card-hints.js`**（`CARD_HINTS`），不再各写一套。

## 二、战斗内「法阵编辑」重排

改成与幕间同一套骨架：

- 顶栏：`法阵编辑 · 暂停中，冷却保留 · 碎片 N`
- 步骤条：默认「1 选牌」；选中手牌后跳到「2 放位」；辅助等待目标时跳到「3 绑定/收回」
- 左：完整 4×4 面板，未解封格也画出「封印」而不是直接消失；可放置空格亮黄框并写「可放置 · 点此」，已占用格写「点此替换」
- 左下详情：选牌时显示待放置卡（图标/效果/操作提示）；点过某格后显示该格详情（名称、间隔/冷却、铭文、出口、辅助目标）；都没选时显示三步操作指引
- 右：手牌列表（每页 5 张 + 翻页），选中行青框；下方卡片详情/操作提示
- 右下：实时校验（`校验通过 · 可完成` 或人话错误），主按钮「完成 · 返回暂停」
- 底部：一行当前状态/操作结果；`E / Esc` 关闭

## 三、幕间「构筑台」同步升级

保留奖励/铭文/誓约/出口玩法，但编辑器部分全部换成共享组件：

- 顶栏副标题合并显示「第 N 幕准备 · 奖励 N 轮 · 已解封 X/16」，不再和出口按钮抢同一行
- 新增同一套三步引导条（在奖励行与法阵之间）
- 格子升级为统一状态：左侧状态条（输出金/辅助青/空位暗紫/封印灰）、铭文黄铜点、出口数、辅助目标箭头；选牌后空格写「可放置」，已占用格写「点此替换」，待绑定格写「待选目标」，合法目标格青框 +「可绑定」
- 手牌面板标题：未选时显示「手牌 X 种/Y 张」，选中后显示「已选 XX · 点左侧空符位放置」
- 状态区新增聚焦格详情行：`5 号 · 寒霜箭  间隔 1.40s / 冷却 1.10s` + `铭文/出口/目标`；誓约与底注重新排距，不再互相压字
- 出口编辑按钮移到手牌标题行右侧，避免盖住引导条

## 四、引导规则（两处一致）

1. **默认**：步骤 1 高亮，提示「点右侧手牌选一张」。
2. **选牌后**：步骤 2 高亮，所有可放空位亮黄框并写「可放置 · 点此」；点击放置 / 替换。
3. **辅助卡放下**：自动进入步骤 3，当前辅助格写「待选目标」，相邻输出格青框写「可绑定 · 点此」；再点自己可取消绑定。
4. **完成**：实时校验草稿；不合法时按钮保持可点但显示人话错误，并自动把焦点带到失效格（沿用原有 syncAuxPending 逻辑）。

## 七、法阵盘追加装饰（2026-11-11）

用户反馈「这个页面里的法阵盘部分多做一点装饰」，在共享层新增 `kitBoard`，两处编辑器自动同步：

- **板框**：4×4 外围双层黄铜框 + 四角 45° 饰角 + 四向罗盘钉（空心菱形 + 短刻）。
- **格间导线**：横竖各三条低透明度铜线，交点一颗小菱形，读作「共振回路」。
- **外轨与刻度**：左右连续铜轨 + 小方钉；面板内壁竖刻、上沿短刻、底边回路节点。
- **格子**：出口在四边中点留 3px 亮刻痕（关掉出口就消失）；四角小铜钉 + 2px 护角；铭文槽改成两颗小菱形（装了填黄铜、空槽只留暗框）；法术图标外套同色细菱形环；名称与状态之间加细分隔线；封印格加交叉蚀刻。
- 四角格额外加金属护角，让整块 4×4 看起来被铜片包住。

所有装饰只画在格子内部留白或格间空隙，不改变文字、图标、点击热区和 51×26 / 104×54 的格子几何；横竖屏共用同一套坐标推导。

四张对比截图已更新到 [editor-unify](editor-unify)。


## 八、法阵盘动态细节（2026-11-11 追加）

用户追加「加入一些动态细节」，新增共享动态层 **`kitBoardMotion(g, opts)`**，由两处编辑器各自以约 **30fps** 调用；所有轨迹都由时间 `t` 确定性推导，不用 `Math.random`，暂停/恢复不会跳帧：

- **板框双跑光**：黄铜主光顺时针绕 4×4 板框一圈，青色副光反向更慢；带拖尾与亮头。
- **外轨垂直跑光**：左右金属外轨各有一段 8px 竖向流光，一金一青反向。
- **格间导线脉冲**：三条竖导线、三条横导线各有一颗青色光点按不同速度流动。
- **四向罗盘扫描**：N → E → S → W 轮流点亮四边中点的菱形罗盘钉。
- **四角符钉呼吸**：四角菱形两两交替明暗，周期约 3.3 秒。
- **法术图标环绕**：每个已放置法术的图标菱形环上有两颗同色小星反向巡游，外环同步呼吸。
- **盘心双星**：板中心两颗 1px 小星缓慢环绕，视线会自然落到法阵中心。
- **聚焦格呼吸**：点过某格后，该格内框以约 1.9 秒周期明暗，四角星点同步闪烁。
- **选牌巡边**：选牌后，每个可放空位的边缘有一颗黄铜小点绕格巡边，比静态黄框更明确。
- **轨道浮尘**：面板左右轨道各有 2 颗极淡的上升尘埃，避免界面完全静止。

性能与边界：动态层只画约 60 个像素矩形，30fps；战斗内只有 `editOpen` 时运行，幕间只有未出发时运行，战斗/结算逻辑完全不读它。关闭编辑、出发、场景 shutdown 都会销毁或清空该层。

验证：`node scripts/editor-motion-check.mjs` 实测战斗内帧数 16→33、幕间 16→32，前后两帧截图字节不同，0 个 pageerror；帧图在 [editor-unify](editor-unify) 的 `motion-*.png`，动图预览见 [motion-preview.gif](editor-unify/motion-preview.gif)。
