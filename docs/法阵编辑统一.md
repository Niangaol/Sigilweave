# 法阵编辑器：一套面板，两处复用

战斗内按 `E` 的暂停改阵与幕间构筑台共用同一套界面组件 `src/ui/editor-ui.js`，卡牌效果文案共用 `src/data/card-hints.js`（`CARD_HINTS`）。这份文档讲界面结构、点击流程、高亮语义和法阵盘装饰层；符位、间隔与冷却的规则数值看 [规则契约](<规则契约.md>)。

## 一、共享组件

| 组件 | 画什么 |
| --- | --- |
| `kitPanel` | 分区面板：不透明底 + 双层黄铜框 + 外描边 + 四角铆钉 |
| `kitHeader` | 顶栏：菱形纹章 + 标题 + 副标题 + 右侧碎片徽章 |
| `kitSteps` | 三步引导条（选牌 → 放位 → 绑定/收回），当前步黄铜、已完成青色，右端可挂一句状态 |
| `kitCell` | 4×4 符位：状态条 + 区位装饰 + 图标 + 名称 + 铭文点 + 出口刻痕 + 目标箭头 |
| `kitHandRow` | 手牌行：图标 + 名称×数量 + 右对齐效果说明，选中整行青框 |
| `kitDetail` | 详情面板：标题 + 可选图标 + 多行说明 |
| `kitAction` | 主按钮：primary 青框亮底，否则暗底黄铜；不合法只降透明度 |
| `kitBoard` | 法阵盘静态装饰（第五节） |
| `kitBoardMotion` | 法阵盘动态层，由两处编辑器各自约 30fps 调用（第六节） |

组件不引 Phaser，文字由调用方传 `text()` 落地，两个 Scene 的容器（`editUI` / `view`）因此能共用同一份界面语言。

## 二、战斗内「法阵编辑」

入口 `E`，`BattleScene.openGridEdit` 建层、`drawGridEdit` 画、`closeGridEdit` 提交并回暂停菜单。逻辑坐标 480×270 上的固定分区：

| 区块 | 位置 |
| --- | --- |
| 顶栏（「法阵编辑 · 暂停中 · 冷却保留」+ 碎片数） | 10,10，460 宽 |
| 三步引导条，右端显示「N 格 · M 空位」 | 10,27，460 宽 |
| 左：4×4 符位面板 | 10,42，224×210；格 51×26，起点 14,56，格距 3 |
| 左下：详情面板（三态） | 10,174，224×74 |
| 右：手牌面板 | 240,42，230×120；行 216×15，首行 244,57，行距 17 |
| 手牌翻页条（多于一页才出现） | 244,144，216×14 |
| 右下：卡片详情 / 提示 | 240,166，230×52 |
| 实时校验行 | 244,222 |
| 主按钮「完成 · 返回暂停」 | 240,234，230×18 |
| 底部状态行（`E / Esc` 关闭提示） | 10,256 |

- **手牌分页**：只列还有余量的卡，**每页 5 条**，`lastPage = ceil(种类数 / 5) - 1`，翻页条写 `◀ 当前 / 总 ▶`，左右半区各一个命中区。
- **步骤高亮**：`auxPending !== null` → 步骤 3；已选牌 → 步骤 2；否则步骤 1。
- **左下有且只有一个面板**：选牌时显示待放置卡（图标 / 名字×数量 / 效果 / 「放置后点完成才生效」）；点过某格显示格详情（名字、间隔/冷却、共鸣、铭文/出口/目标）；都没选时是三步操作指引。

### 点击流程

1. 点手牌行：选中（再点一次取消），同时清掉待绑定的辅助。
2. 点符位：未解封只提示「N 号尚未解封，不能放置」；已解封时空位放下、有卡则替换（原卡退回手牌）、点自己已放置的卡是收回。
3. 选牌优先于绑定：等着绑目标时选一张牌，会先按「放牌」处理，不会卡在绑定态。
4. 辅助卡放下后进入绑定态：本格写「待选目标」，四邻输出格青框写「可绑定 · 点此」；再点自己取消。绑定当场校验：目标必须相邻且装着符印，不合法只提示、不记账。

### 校验与提交

- 校验入口是 `src/logic/build.js` 的 `validateDraft` + `explainBuildErrors`，0 错误时校验行写「校验通过 · 可完成」，主按钮转 primary。
- 主按钮**一直可点**。有错时 `closeGridEdit` 不关面板：先 `syncAuxPending()` 把焦点送到缺目标的辅助格，送不过去就把人话错误写进底部状态行，面板保持打开。
- 通过后 `applyDraft(..., { preserveFrom })` 只提交槽位、把每格 `cooldownUntil` 原样带过去——改阵不重置冷却；随后重建派生值、重放罗盘乘算与联组目录，再 `openPause('menu')`。
- 命中区全部收在 `this.editRects`，指针坐标先除以 `getRenderScale()` 换算成逻辑坐标；悬停层 `editHoverG` 画亮框 + 手型光标。

## 三、幕间「构筑台」

`IntermissionScene.paint` 用同一批组件，差异只在数据和奖励/铭文/誓约/出口这些幕间专属区：

- 顶栏副标题合并成一句：「第 N 幕准备 · 奖励 N 轮 · 已解封 X/16」，右侧碎片徽章。
- 引导条和战斗内同组件同语义，位置随布局（`14, infoY-3`，440 宽）。
- 手牌标题：未选时「手牌 X 种 / Y 张」，选中后「已选 XX · 点左侧空符位放置」。幕间**不翻页**，横屏最多列 5 行、竖屏 6 行。
- 统计区三行：输出 / 辅助 / 空位；聚焦格「N 号 · 名字　间隔 x.xx s / 冷却 y.yy s」；铭文 / 出口 / 目标。
- 出口编辑是覆盖面板，不改法阵本身；入口按钮横屏在 `390,74`（70×12），竖屏挪到标题行右侧 `386, handPanel.y+2`（78×16），不盖引导条。

## 四、符位格子怎么读

| 元素 | 含义 |
| --- | --- |
| 左侧 2px 状态条 | 输出金 / 辅助青 / 带进化更亮 / 空位暗紫 / 未解封石色 |
| 左上 2×2 派系色点 | 该符印所属派系；共鸣生效时外加一圈白框 |
| 右上金星 | 已进化 |
| 右上三角 / 菱形 | 变体：锐 = 血橙三角，谐 = 青绿菱形；基础形态不标 |
| 区位装饰 | 由 `src/ui/board-decor.js` 的 `decoratePlan` 按角落 / 边 / 中心三档给不同刻线（见下节） |
| 四边中点亮刻痕 | 出口；关掉某一边就消失，不用只看「出 N」 |
| 两个小菱形 | 铭文槽，装了填黄铜、空槽只留暗框 |
| 青色箭头 | 辅助指向的目标格号 |
| 交叉蚀刻 + 「封印 / N 号 · 未解封」 | 未解封格，画出来而不是直接消失 |
| 铜片护角 | 四角格（0/3/12/15）额外包边，整块 4×4 读作被铜片压住 |

高亮文案只有四种，两处一致：`可放置 · 点此`、`点此替换`、`待选目标`、`可绑定 · 点此`；无高亮时是 `N号 铭x 出y →目标` 或 `N 号 · 从手牌放入`。

## 五、法阵盘装饰

`kitBoard` 只画在格子内部留白或格间空隙，不碰文字、图标和点击热区：

- **板框**：4×4 外围双层黄铜框 + 四角 45° 饰角 + 四向罗盘钉（空心菱形 + 短刻）。
- **格间导线**：横竖各三条低透明铜线，交点一颗小菱形，读作「共振回路」。
- **外轨与刻度**：左右连续铜轨 + 小方钉；面板内壁竖刻、上沿短刻、底边刻度与三颗回路节点。
- **区位三档**：`cellZone` 把 16 格分成角落 4 / 边 8 / 中心 4——角落是护角 + 铆钉 + 略暗石面，边是单条外侧栏 + 两端小钉，中心是淡符文方框 + 两侧刻点，不压符印。

格子几何不进装饰层：横屏 51×26、竖屏 104×54（竖屏 `glyphScale 2`、名称 10 号、明细 8 号），横竖屏共用同一套坐标推导。

## 六、动态层（约 30fps）

`kitBoardMotion(g, opts)` 每帧只清空自己那层再重画，全部轨迹由传入的 `t` 确定性推导，不用 `Math.random`，暂停 / 恢复不会跳帧：

| 动效 | 节奏（源码常量） |
| --- | --- |
| 板框双跑光 | 黄铜主光顺时针一圈 3.6s、拖尾 10 点；青色副光反向、拖尾 6 点 |
| 格间导线脉冲 | 三条竖线各一青点（1.5s 一轮，相位差 0.31），三条横线各一（1.9s，相位差 0.43） |
| 外轨垂直跑光 | 左金 2.4s、右青 2.9s，各 8px 长 |
| 四向罗盘扫描 | N → E → S → W 每 480ms 换一个 |
| 四角符钉呼吸 | 周期约 3.3s，金青交替 |
| 图标双星环绕 | 已放置法术的图标菱形环上一颗同色星绕行（0.9s 一圈），反向再补一颗 |
| 聚焦格呼吸 | 内框与四角星点随 `t/300` 明暗 |
| 选牌巡边 | 每个可放空位边上有一颗黄铜小点绕格跑 |
| 盘心双星 | 两颗 1px 星在半径 19 / 22 上慢转，视线自然落到盘心 |
| 轨道浮尘 | 面板左右各 2 颗上升的极淡尘埃 |

边界：战斗内只有 `editOpen` 时才在 `tickEditBoardMotion` 里累计（间隔 <33ms 直接跳过），关编辑即销毁；幕间只有未出发时跑，`departed` 后 `clear()`；场景 shutdown 一起清。战斗与结算逻辑完全不读这层。
