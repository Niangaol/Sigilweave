# 编辑界面「改了法术就报 aux need target」修复记录

> 用户反馈（2026-10-24）：「有的时候在编辑界面更改法术会报错：aux need target」

## 一、根因（已用真实点击复现）

指向型辅助（**时之沙漏 / 扩域符文 / 献祭**）必须绑定一个**相邻符印格**作为作用目标，
校验里叫 `aux_needs_target`。它本身是对的，出问题的是**编辑流程**：

1. 时之沙漏放在 6 号格，指向 7 号格的符印 → 合法。
2. 玩家把 7 号格换成别的卡（这就是「更改法术」）。
3. 换卡逻辑会顺带清掉「指向这一格」的辅助目标（`delete draft.auxTargets[src]`）——
   **这一步是静默的**，界面上没有任何提示。
4. 玩家点「完成」，`validateDraft` 报 `aux_needs_target`，界面直接把**内部错误码**打在提示条上：
   `未通过校验：aux_needs_target`。

三个具体缺陷：

| # | 缺陷 | 后果 |
| --- | --- | --- |
| 1 | 目标被连带清掉时不提示 | 玩家不知道自己弄坏了哪个格子 |
| 2 | 报错只给内部编码 `aux_needs_target` | 看不懂、也不知道该改哪一格 |
| 3 | 暂停编辑器的绑定点击**不校验目标** | 随便点一格也会被记成目标，到「完成」才报 `aux_target_invalid` |

## 二、改法

### 1. 错误码翻成人话（`src/logic/build.js`）

```js
explainBuildErrors(errors, draft)
// → '6号位「时之沙漏」：还没选作用目标（要指向一个相邻的符印格）'
```

带上「几号位 + 卡名 + 中文说明」，未知编码才回退成原码。

### 2. 目标失效时把人直接带到那一格（两个编辑器都改）

- 新增 `missingAuxTargets(draft)`（哪些指向型辅助的目标失效/缺失）
  与 `auxTargetCandidates(draft, cellId)`（这一格能指向谁）。
- 放置/收回卡牌后立刻体检：一旦发现别的辅助目标被弄坏，**自动进入那一格的绑定模式**，
  该格描成暖金 2px 边框、副标题写「待选目标」，提示条说明「6 号「时之沙漏」的目标失效了：点一个相邻符印重新绑定」。
- 点「完成」时如果仍然缺目标，也走同一条路（不再只弹错误码）。

### 3. 修掉三个会把人卡死的死路

| 死路 | 处理 |
| --- | --- |
| 绑定点击不校验，随便点都算目标 | 点下去就校验「正交相邻 + 装着符印」，不合格当场说明原因 |
| 等待绑定时点不了手牌，想补回符印都做不到 | **选牌优先**：手牌选中时点击优先按「放置」处理 |
| 相邻根本没有符印可指，却硬进绑定模式 | 先算候选：没有候选就不进绑定模式，提示「请收回或换个位置」 |
| 已经进绑定模式但想退出 | 再点自己那一格 = 取消绑定 |

### 4. 幕间工作台同步

`canDepart` 不再输出 `构筑校验未通过：aux_needs_target`，改为
`还没法出发 — 6号位「时之沙漏」：还没选作用目标…`；点「确认构筑 · 出发」失败且缺目标时，
同样直接切到那一格的绑定模式。

## 三、验收

- 单元测试：`tests/aux-target-hint.test.js`（12 条）覆盖目标体检、候选计算、错误翻译，以及
  工作台换卡后出发提示不再泄露内部编码。
- 真实鼠标点击回归：`node scripts/aux-target-check.mjs`（dev server 在 5180）。
  完整跑通「放沙漏 → 绑 7 号 → 把 7 号换成辅助卡 → 点完成 → 补回符印 → 重新绑定 → 完成退出」，
  全程 `pageerror` 为 0，提示条从来没有出现 `aux_needs_target` 字样。
- 其它回归：`node scripts/workshop-smoke.mjs`、`node scripts/pause-edit-smoke.mjs` 通过；
  `npx vitest run` 659 条全绿；`npm run build` 通过。
