# 问答文案提取稿（改稿本 v2）

> 12 条遭遇问答的**全部玩家可见文案**，从 `src/data/encounters.js` 原样导出，未做任何改写。
> 全文可见文案合计 **1939 字**（含选项与线索）。修饰由你自己动，本稿只负责「一次看全、照着改、改完能自查」。

## 一、改稿只碰三个地方

| 改什么 | 文件 | 注意 |
| --- | --- | --- |
| 12 条问答的线索 / 题面 / 选项 / 解析 / 答对答错 / 名号 | [src/data/encounters.js](src/data/encounters.js) | 只替换字符串，**id 和数值别动** |
| 面板固定文案（8 条：破局成功、确认作答……） | [src/ui/EncounterPanel.js](src/ui/EncounterPanel.js) | 同一句在横屏/竖屏各写了一次，**两处都要改** |
| 改完自查 | [tools/qa-copy-lint.mjs](tools/qa-copy-lint.mjs) | `node tools/qa-copy-lint.mjs`，见文末 |

## 二、不能碰的硬约束（来自测试与设计稿）

1. **12 条题面必须互不相同**（tests/encounters.test.js 第 29 行硬校验）——改得太像测试会挂。
2. **所有 Boss（6 条）的答对正文必须含"无需战斗"四个字**（第 55 行）。
3. 每条固定 3 个选项、id 唯一、正确项唯一；**只改 label，别改 id**，正确答案靠 id 而不是显示顺序。
4. 数值是硬校验：NPC = 8 碎晶 + 15 生命，答错迟缓 8 秒；小 Boss = 6 碎晶；大 Boss = 4 碎晶。**文案里提到的数字必须与之一致**。
5. 设计稿规则：答案必须能从**本条线索**直接推出，线索只能用本局已展示的对白/碑文，不考课外设定（`共振法阵_游戏设计稿_v2.0.md` 第 1425 行）。

## 三、篇幅账本：不改面板还能加长多少

横屏面板 480×270，可用正文宽 416px。实测当前值与容量上限：

| 字段 | 当前最长 | 横屏上限 | 剩余空间 |
| --- | --- | --- | --- |
| 面板标题（name·title） | 18 字 | 32 字 | 14 字 |
| 线索合计 | 73 字（boss-1） | 138 字 | 65 字（约 1.4 行） |
| 题面 | 23 字 | 82 字 | 59 字 |
| 单个选项 | 7 字 | 12 字 | 5 字 |
| 答对/答错正文 | 37 字 | 111 字 | 74 字 |
| 解析 | 37 字 | 225 字 | 188 字 |

> 结论：**不动面板也能把文案写长 2~3 倍**（解析甚至能到 6 倍）。
> 只有超过上面「上限」才需要动版式，那时再叫我调 [EncounterPanel.js](src/ui/EncounterPanel.js)。

## 四、现有文案的重复句式（修饰时最值得打散的地方）

- 12 条题面里 **9 条**用了「应…」句式，其中 4 条直接以「应」开头（npc-3、boss-2、miniboss-1a、miniboss-3b），是最重的公文腔。
- 三条 NPC 的答对正文结尾高度雷同：「…赠你 8 碎晶，并为你恢复 15 点生命」×3。
- 三条大 Boss 的答对正文统一收在「无需战斗。额外获得 4 碎晶。」×3。
- 六条小 Boss 的答对正文统一收在「无需战斗」×6。
- 线索里说话人前缀（"守灯人：""石碑：""断剑铭文："）格式不统一：有的是人名，有的是物件。

## 七、改完怎么自查

```bash
# 1) 文案硬约束 + 篇幅告警（秒出，不用起服务）
node tools/qa-copy-lint.mjs

# 2) 官方单测（文案相关断言在这里）
npm test

# 3) 浏览器里的真实点击回归（改了版式才需要；先 npm run dev）
node scripts/encounter-smoke.mjs
```
