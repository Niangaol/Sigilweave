# 问答文案提取稿

改稿底本：34 条遭遇问答的全部玩家可见文案，逐字抄自 `src/data/encounters.js` 的 `ENCOUNTERS`，一个标点都没动——要改字就对着这里改，改完再抄回去。配套 [内容规格表](<内容规格表.md>) 的遭遇条目与 [规则契约](<规则契约.md>) 的问答结算一起看。

改哪里：只换 `ENCOUNTERS` 里的字符串字段——`name`、`title`、`clues[].text`、`question`、`choices[].label`、`explanation`、`successText`、`failureText`。`id`、`type`、`tier`、`bossId`、`correctChoiceId`、`reward`、`penalty` 是硬结构，不动。

会红的测试：`tests/encounters.test.js`（34 条的数量与 ID 集合、名字与题干唯一、小 Boss 收尾语、奖励数值）；`name` 在代码里有两份——`ENCOUNTERS` 和 `src/data/map-events.js` 的 `STAGE_THEMES`（事件点上的名字），后者那七个 NPC 名被 `tests/map-events.test.js:21-27` 锁着；加减一条还会撞 `tests/meta-data.test.js` 的 20 条小契约和 `tests/map-events.test.js` 的 27 个事件点。

## 一、每条怎么读

- 小节标题：`#### id · 类型 · 场 N（第 X 幕）· 名字「头衔」`，方便整条摘出去单独对照。
- 线索抄的是 `clues[].text`，反引号里是 clue id；面板会把同一条遭遇的所有线索用空格拼成一行显示。
- 选项按 `choices[]` 的数据顺序列出，✔ 就是 `correctChoiceId`。开局时按种子洗牌，位置会变，判对只认 id。
- 解析、答对、答错都是玩家会读到的正文；奖励与惩罚是该条的 `reward` / `penalty`，由场景在确认作答后消费一次。
- 幕与场是两套编号：场 1–3 各自成幕，第四幕 = 场 4 + 场 5，第五幕 = 场 6 + 场 7（`src/logic/acts.js` 的 `chapterOf`）。

```bash
node tools/qa-copy-lint.mjs                                                                              # 篇幅：34 条是否还在横屏面板预算内
```

`tools/qa-copy-lint.mjs` 的 ID 硬校验没跟上 34 条，跑起来会先报一条「遭遇 ID 集合变了」——忽略这条，它的容量表（标题 32、线索 138、题面 82、单选项 12、正文 111、解析 225 字）仍然有效，34 条现在全部在预算内。

篇幅超了不只是面板要调：`scripts/encounter-smoke.mjs` 与 `scripts/progression-smoke.mjs` 按坐标点击，版式一改就得同步改。
