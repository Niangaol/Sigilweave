## 本轮变更

- 重构 [构筑模块](<../src/logic/build.js>)：校验幕数、格号、重复解封、各层定义、互斥主槽、铭文槽、出口及辅助目标。
- 有目标的辅助必须指向已解封的正交输出邻格；空格、辅助、自身、对角与字符串格号均不能作为目标。
- 定义查找使用自有属性检查，constructor／toString 等继承字段不再被当成合法内容。
- 先建立临时法阵、派生值和快照，再一次提交；失败返回结构化错误，不清空旧构筑。
- 快照与草稿采用同一 JSON 数据形状，包含幕数、誓约、主槽、两个铭文槽、出口和辅助目标；不包含跨幕无意义的运行时冷却。
- 快照递归冻结，提交及回读均复制可变数据；编辑草稿不会反向改变法阵或已提交快照。
- 解封目标只接受 0—16 的整数，非法目标不产生任何修改。

## 接口边界

- emptyDraft(act)：新草稿，版本 1。
- validateDraft(draft)：返回错误列表，默认执行当前幕解封数量限制。
- applyDraft(grid, draft, options)：失败返回 ok:false；成功返回 ok:true 和只读 snapshot。传入 phase 时仅 intermission 允许提交。
- draftFromGrid(grid)：创建可编辑副本。
- snapshotBuild(grid)：创建完整只读快照。
- unlockToTarget(grid, count)：确定性解封，不因目标降低重新封格。

实际场景状态及资源所有权仍由后续幕间系统负责。纯数据模块的 phase 参数不是访问控制机制；接 UI 时必须从场景真实状态取值，不能让玩家传入状态绕过战斗禁改阵。
